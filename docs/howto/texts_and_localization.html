Texts and translations

Every word a player reads in Outlaw Survivors, where it lives, how to change it in the Level Editor's Texts tab or in Excel / Google Sheets, and what keeps a change from breaking the game. Pass 137.

Where a text lives

Each text has a key, a short dotted name such as ui.portal.extract or weapon.revolver.name. Every text lives in exactly one place:

WhatWhereExample key
An item's, Outlaw's or creature's own words (name, flavour, a mutation's text, a trait)its own JSON, as before: content/weapons/revolver/revolver.json → nameweapon.revolver.name
A skin's namethe Outlaw's JSON, variants.DRI-B.skin.nameoutlaw.drifter.skin.dri_b.name
The Trail's section and upgrade words, the Wanted tasks' wordscontent/trail/trail.json, content/wanted/wanted.jsontrail.upgrade.might.name
Everything the code says: screens, buttons, toasts, hints, the generated card sentencescontent/strings/en.json (the string table)ui.stranger.deal, gen.weapon.shot.priority

The tab shows all of them together, and saving writes each one back where it lives. You never need to know which file a row is in; the grey line under the key says it anyway.

The key's first word tells you what it belongs to: ui. a screen, toast. / hint. a message, gen. a sentence the game builds for many items (a template), stat. a stat's name, weapon., passive., outlaw., enemy. ... one item. The middle word of an item key is the item's folder name (its id).

The Texts tab

  • Sub-tabs along the top group the rows: Outlaws, Enemies & Bosses, Weapons, Mutations & Evolutions, Cards & Items, Quests / Wanted / Trail, Stages & Structures, Stats, Screens, Messages, Words. The number is how many rows each has.
  • Search looks through every key and every text in all sub-tabs at once.
  • Each row: the item's icon (none for screens), the key and its file, the text you edit, its variables as chips with the value the game last gave them, and reads: the text as the game would show it with those values.
  • An edited row turns gold. Undo on the row puts it back; Revert forgets every edit; changed since the last save shows only the edited rows.
  • Save (or Ctrl+S) writes every edit where it lives, keeps a backup of each file it touched, and imports the content folders it changed. The game reads the texts when it starts: restart it, or ship a build, to see them.

Variables: {amount} and {amount?shot:shots}

A text that holds a number or a name has a variable in curly braces. The game fills it in; you decide the words around it.

Fires {amount} {amount?shot:shots} within {range} m and aims at {who}.
  → Fires 1 shot within 14 m and aims at the strongest enemy nearby.
  → Fires 3 shots within 14 m and aims at the strongest enemy nearby.
WriteMeans
{amount}the value, exactly as the game formats it ("3", "1.5", "07:10", "Lv 12")
{amount?shot:shots}the first word when the value is exactly 1, else the second (plural). Either side may hold another variable: {amount?a spear:{amount} spears}
{{ and }}a brace that shows on screen

The names are short and say what the value is in that row ({amount}, {range}, {pierce}, {who}, {seconds}, {gold}). A row can only use the variables it already has (the chips): the code hands in those and no others. You may move them, drop one (the tab warns), or use one twice.

"Exactly 1" means the value 1: "1.0 s" picks the plural. Numbers are formatted by the game, so a text never changes how a number looks.

Editing in Excel or Google Sheets

  1. Export all (CSV) or Export this tab. The file has five columns: key, group, text, variables, where.
  2. Open it in Excel (double-click works: the file says it is UTF-8) or import it into Google Sheets. Change only the text column. Leave the keys alone; delete rows you did not touch if you like (a missing row means "no change").
  3. Save as CSV UTF-8 (Excel: File → Save As → "CSV UTF-8 (Comma delimited)"; Google Sheets: File → Download → CSV).
  4. Import CSV… in the tab. Nothing is written yet: you see "12 texts change: ..." with every old and new text, the errors (by line) and the warnings. Apply these changes writes them, exactly as a Save would.

Line breaks inside a cell are kept. Curly quotes (“ ” ’) are fine.

One error anywhere means nothing is written; fix it and try again. Every save keeps a backup of each file in tools/level_editor/backups/. If the game ever meets a key it cannot find it shows the key itself (ui.portal.extract) instead of crashing, and the tests fail on it before a build ships.

What happens with new content

A new weapon folder still gets its card sentence with no new row: the game first looks for the weapon's own row (weapon.<id>.desc), and when there is none it uses the shared template for that kind of weapon (gen.weapon.shot.priority and friends, in the Words and Weapons sub-tabs). Its name and flavour live in its JSON as always and show up in the tab by themselves. To give one weapon its own wording, ask Claude for its weapon.<id>.desc row (it starts as a copy of the template; then edit it here).

Since pass 137 every word a player reads is in the tab: every screen, button, toast and hint, every card sentence (every weapon and evolution has its own row), the stats' names and the Trail's words. They moved without a word changing. The developer screens (the developer menu, the arena, the debug panels, the Watch) stay in code: no player reads them. The stage names show in the tab but are edited in the Timeline tab.

Other languages, later

Only English exists now. A second language will be one more file beside en.json (content/strings/de.json, say) with the same keys; any key it lacks falls back to English, so a half-done translation never shows a blank. Items' own words translate under the same keys the tab shows (weapon.revolver.name), so the JSON stays the English source. The CSV will grow one text column per language.
