## F1. Brief factual architecture map

### 1.1 What exists (evidence: the code as read)

**Frontend** (`tools/level_editor/*.js`, `index.html`, `style.css`): one static page, vanilla JS, no framework, no bundler, no `package.json`; `index.html:100-148` loads 38 classic `<script>` tags (36 at HEAD; the critic's count: the map's "~43" was wrong); only `vendor/` (model-viewer) is third-party; 58,555 lines including selftests. `App.render(tab)` clears and rebuilds the active tab's panel (`app.js:1037-1060`). The Jobs tab **polls** `GET /api/jobs?since=<rev>` every 2 s while on screen, 6 s otherwise, 15 s when the API answers 404/503, nothing while hidden (`jobs.js:41, 328-345`); the server answers `{rev, unchanged: true}` when nothing changed, **else the whole list** (`jobs.py list()`), which part_UI measured at **3,316 KB** serialised for today's 467 records. The **card rebuild rule**: a running job's signature includes `Math.floor(Date.now()/2000)` (`jobs.js sig()` 614-617), `draw()` clears every group and re-appends (619-658), so a running card is rebuilt every poll and any group count change rebuilds all its cards; a waiting card's picked candidate (`c.__picked`), an open re-roll panel and the log scroll live on the DOM node and die with it. The house pattern that does it right: `looks.js` keeps grid state in a `states` Map and redraws only on a real change, never under an open edit (36, 100-102, 455-466). The Drivers tab (`drivers.js`, pass 93) is the one per-frame viewer (scrub, big index, numbered contact sheet, a pick mode); `strip_player.js` plays strips exactly as the game indexes them. **No push channel**: grep finds no `EventSource`, `WebSocket` or `text/event-stream`.

**Server** (`tools/level_editor/server.py`, 4,527 lines): stdlib `ThreadingHTTPServer` on `127.0.0.1:<port>` (8787 or the next free), no auth, HTTP/1.0 with Content-Length on every reply, one process that also hosts the job workers. Content writes are line-preserving (`content_io.set_top_block` / `set_variant_entry`: edit as text, re-parse, compare; refuse with "layout ..." when the layout cannot be kept) under `_write_lock` with a backup per write (`KEEP_BACKUPS` 30) and `write_atomic`; after a save, `run_import` runs `import_json.gd -- only=<type>/<id>` under the Godot lock or queues an `import` job. The `Hooks` class (3118-3390) is the contract jobs land through: `merge_look` (the sidecar entry merged, `fresh: true`), `merge_top`, `set_recipe`, `merge_recipe`, `set_look_files` (icons via `set_look_icon`: `icon_history` + a backup copy), `redump_merge`, `snapshot_icons`, `look_records`, `content_path`. Look ops (`look_op`): approve, shelve, unshelve, remove (files to `backups/deleted/<id>/<stamp>/`), note, recipe, default.

**Jobs** (`tools/level_editor/jobs.py`, 4,815+ lines; `tools/asset_job.py`): `tools/dl/jobs/queue.json` `{rev, jobs[]}` rewritten whole on every `_save()` (4.0 MB; 467 records, rev 6766: done 429, cancelled 28, failed 8, interrupted 2; kinds icon_cands 225, import 116, look 60, install 32, hero_badge 12, hero_title 11, sim 6, register 4, launch 1; never pruned) plus a folder per job (`job.json`, `log.txt`, `result.json`, `workflows/`). One claimant process (`claim_queue` takes the `jobs` lock with the port in its note; a live second editor is read-only; `recover()` marks running jobs `interrupted`, reclaims dead-pid locks). Four lanes (`comfy`, `godot`, `local`, `sim`), one daemon thread each, FIFO per lane with `front` and `held`. State machine `queued -> running -> done | failed`, `running -> waiting -> pick -> queued` for the human picks, `cancelled`, `interrupted`. `_plan` maps kind+method to an `asset_job.py` subprocess (`ASSET_JOB_SIDECAR=<job>/result.json`), a `steps` list, a launch or a sim. Progress = `parse_line` regexes over the tool's stdout (`render <key> seed N 12.3s ok`, the clip lines, "kept the best", the stop markers) + `_check_caches` every 5 s; **granularity one still or one clip, never a frame or a ComfyUI node**. Landing: `_after_exit` -> `_post` reads `result.json`, merges through the hooks, `_harvest` lists outputs, `_after_done` queues an `import` job. Re-rolls move clip folders to `_old<stamp>` and advance seeds; cancel kills the tree and POSTs `/interrupt` **and `/queue {clear: true}`**.

**Generation** (`tools/gen_art.py`, `gen_ctl.py`, `animate.py`, `artkit.py`, `puppet.py`, `recolour_strip.py`): stills cached `tools/dl/ai_raw_anime/<key>.png + .json` (seed, prompt, refs, the LM Studio `qa()` report, geometry); clips cached `tools/dl/ai_anim/<key>/{out_NN, full_NN, cycle.json}` with per-kind cache-fit rules; frames scaled by a whole-clip statistic (`clip_scale`; gen_ctl: ONE scale for all five views), placed (`place_clip_frames`), colour-corrected, assembled with the procedural sets, packed (`pack_strip`), and the strip + icon **written straight into `game/content/...`** over the previous file; under a job the entry goes to the sidecar, in a hand run the JSON is re-dumped whole (`gen_art.py:1922-1937`). Sizes: 661 clip folders 8.3 GB (666 at 18:40), 3,262 files in `ai_raw_anime` 1.3 GB (each still with its json; 1,633 stills). The only vision QA: `gen_art.qa()` on stills (subjects, background, ground, text, cropped, legs, view, matches) through LM Studio `qwen2.5-vl-7b` and one "faces the viewer?" probe on back/bd pose cycles; never per frame.

**ComfyUI client** (`tools/comfy.py`): `run(graph)` POSTs `/prompt` with a fresh `client_id` then polls `GET /history/<id>` every 1 s; no WebSocket, no node progress; the comfy lock is taken for the whole tool process, no fairness; every graph is saved per job and PUT into the ComfyUI page's user data so a card can open it (`88fits_open`). Graph builders: `klein`, `flux2_dev`, `wan_i2v`, `wan_flf`, `wan_fun_control`, `wan_animate`, the Hunyuan3D graphs, audio, and (in flight) `wan_fun_vace`.

**The installed artifact and the game**: the strip `<id>_sprite[_<x>].png` of square `frame_px` cells, `strip_cols` columns, animations in a fixed order with counts in `anims` (`artkit.ENEMY_ORDER` / `CHAR_ORDER`, `EnemyDef.gd:591-600`, `Player.gd:187`); the look entry `variants[CODE]` = `sprite, icon, anims, strip_cols, fps, head, frame_px (heroes), front_faces/back_faces, note, shelved, fresh, icon_picked, title, recipe`. **No per-frame metadata exists anywhere**; the slot-to-source mapping is recomputed at pack time and never written. The game loads `<id>.tres` at boot (`Registry.gd:67-71`), plays the human-set `variant` / `Save.hero_look` (`Registry.played_look`), one MultiMesh per creature type with `frames/cols/rows` uniforms (`EnemyManager.gd:946-984`).

**Entry points for Claude Code today**: the tool CLIs (each takes its own locks), `POST /api/jobs {kind, target, spec, title}` -> `{job}`, `GET /api/jobs[?since]`, `GET /api/job/<id>` (the record with an 80-line log tail), the `cancel/requeue/pick/install/move/delete/merge/push_workflows` POSTs; `puppet.py stage_looks` is the one script that drives the queue over HTTP. No MCP; no compact result: a job's `outputs[]` are URLs plus a QA problems list per still.

### 1.4 Top five verified blockers to the desired UX

1. **A frame has no identity and no durable home.** Every look run rewrites the strip whole (`gen_art.process` / `gen_ctl.main` `strip.save`), recolour rewrites its destination, and clip frames exist only as cache files that re-rolls move aside (`_move_clips_aside`), that `animate.cache_fits`/`wan_fits` invalidate, that free clips re-cut from `full_NN` (`animate.cycle` 623-635). Map §4.4 shows layer by layer that **no existing layer survives the normal fix paths**; the only safe insertion point is a new per-slot store between the clip cache and the pack, read by an Export that packs with a pinned scale. *Built (lane VACE)*: `frames_store.py` + `frames_export` is exactly that layer, and `gen_art`/`gen_ctl` now register their frames through `hook_after_save` (AN-10); what still overwrites the game's strip on pinned slots is a landing or a hand run, which *revision 2* closes with Garry's point 4 (the pins re-applied at every landing, AN-09).
2. **State reaches the browser by pull only, at still/clip granularity.** The page polls `rev` every 2 s and gets the whole 3.3 MB list on any change; progress is stdout regexes and cache-file existence; ComfyUI progress is never bridged (the tool polls `/history`; the server never talks to ComfyUI during a render).
3. **The Jobs UI rebuilds DOM on change and keeps interaction state on the DOM** (`sig()`'s time term, `clear(S.groups)`, `c.__picked`, `.jreroll`, the re-pinned log, `assets.js refreshRecord -> redraw` rebuilding the whole editor pane). Structural, not a bug.
4. **Generation, installation and import are one motion with no commit boundary.** The tool writes the PNG into `game/content` as it finishes; `merge_look` sets a page-only `fresh` flag the game ignores; no previous strip is kept (icons are protected, strips are not); a hand run re-dumps the JSON outside the line-preserving writer.
5. **No evaluator looks at frames, and Claude has no compact result.** The only automatic judgments are `qa()` on stills and a few clip heuristics at generation time; a job returns URLs and a log tail, so a session that wants a verdict opens pictures (the spend of 2026-10-20). Related and verified: the comfy lock has no fairness and a hand run can hold it for a whole pass; `_comfy_interrupt` clears ComfyUI's **whole** queue on cancel (an interference bug lane REAL hit the same day).

#### D1 UI (part_UI.md)

**UI-01 (accepted as a later phase; revision 1 had rejected it as proposed).** A stream's cadence is bounded by what the server knows: a running record changes when a tool line arrives (`_on_line`), saved at most every 2.0 s (`SAVE_THROTTLE`) or on a cache check (5 s); the unit is a still or a clip. SSE on `BaseHTTPRequestHandler` is feasible (headers without Content-Length, a flush per change, a heartbeat comment every 15 s, one daemon thread per stream, `EventSource` reconnects with `Last-Event-ID` = `rev`), about 150 server lines and 60 client lines, but it adds a thread per tab, a wake-from-sleep failure mode and a file-watch loop for the read-only editor, for ~2 s of latency nobody sees. The dead-simple improvement nobody has made: `parse_line` already recognises `render <key> seed N 12.3s ok`; harvesting outputs on that line instead of on the 5 s workflows-folder check shows a landed still within one poll. The bus is designed so the transport can change underneath it: the page consumes `{rev, changed, removed}` whether it polled or was pushed. Done when a changed poll while one job runs transfers kilobytes, not megabytes. *Revision 2*: Garry's point 11 keeps streaming on the roadmap, so the SSE design above is Phase 4's step 4.10, built on `events.jsonl`'s `seq` once WF-07's progress lines and the request loop's events give it something sub-2-s to carry; the same `{rev, changed, removed}` consumer, the poll as the fallback.

#### D2 WF (part_WF.md)

## F6. Critical recommendations

### Top five highest-ROI improvements, ranked (revision 2)

1. **One-command delegation with the auto-iterate loop (AI-05 + WF-01/WF-03/WF-05 + AI-04; Garry's points 6 and 13).** Claude queues with one command and reads one paragraph; the loop does the evaluate / adjust / re-roll / repair / provisional-pick work within a budget and hands Garry one approval box. 2. **The frame layer lane VACE built: preserve it, finish Garry's three changes to it (AN-09's batch confirm and pin re-apply, AN-07's label, AN-14's no-deletion).** It is the only insertion point that survives the normal fix paths (blocker 1), it runs end to end on SP-B with rollback, one writer and the confirm, and it is what makes the loop's provisional winners safe (staged, never installed).
3. **UI-04, stable cards.** The verified daily annoyance (a running card rebuilt every 2 s, picks and panels lost), fixable in one module with the pattern `looks.js` already follows; it de-risks the request card, the look card's live block and the Frames view.
4. **AI-07's tiers with AI-01's ledger and the Gemini backend, gated by AI-08's blind bench (Garry's point 7).** Deterministic checks on everything, the free local eye on flagged frames, a metered cloud eye on contact sheets at decision points under configurable ceilings; the bench stops money being spent on an eye that cannot count and measures whether Gemini can.
5. **UI-02's delta protocol and connection line, with WF-06(c)'s cancel fix, then SSE (UI-01) once WF-07 ticks.** A changed poll goes from 3.3 MB to kilobytes, "offline" becomes a true sentence with a time, a reload returns to the same frame or request, a Stop never clears a hand run's ComfyUI prompt, and the stream Garry wants arrives on the same consumer when there is something sub-2-s to carry.
