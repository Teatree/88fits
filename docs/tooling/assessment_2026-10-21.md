## F1. Brief factual architecture map

### 1.1 What exists (evidence: the code as read)

**Frontend** (`tools/level_editor/*.js`, `index.html`, `style.css`): one static page, vanilla JS, no framework, no bundler, no `package.json`; `index.html:100-148` loads 38 classic `<script>` tags (36 at HEAD; the critic's count: the map's "~43" was wrong); only `vendor/` (model-viewer) is third-party; 58,555 lines including selftests. `App.render(tab)` clears and rebuilds the active tab's panel (`app.js:1037-1060`). The Jobs tab **polls** `GET /api/jobs?since=<rev>` every 2 s while on screen, 6 s otherwise, 15 s when the API answers 404/503, nothing while hidden (`jobs.js:41, 328-345`); the server answers `{rev, unchanged: true}` when nothing changed, **else the whole list** (`jobs.py list()`), which part_UI measured at **3,316 KB** serialised for today's 467 records. The **card rebuild rule**: a running job's signature includes `Math.floor(Date.now()/2000)` (`jobs.js sig()` 614-617), `draw()` clears every group and re-appends (619-658), so a running card is rebuilt every poll and any group count change rebuilds all its cards; a waiting card's picked candidate (`c.__picked`), an open re-roll panel and the log scroll live on the DOM node and die with it. The house pattern that does it right: `looks.js` keeps grid state in a `states` Map and redraws only on a real change, never under an open edit (36, 100-102, 455-466). The Drivers tab (`drivers.js`, pass 93) is the one per-frame viewer (scrub, big index, numbered contact sheet, a pick mode); `strip_player.js` plays strips exactly as the game indexes them. **No push channel**: grep finds no `EventSource`, `WebSocket` or `text/event-stream`.

**Server** (`tools/level_editor/server.py`, 4,527 lines): stdlib `ThreadingHTTPServer` on `127.0.0.1:<port>` (8787 or the next free), no auth, HTTP/1.0 with Content-Length on every reply, one process that also hosts the job workers. Content writes are line-preserving (`content_io.set_top_block` / `set_variant_entry`: edit as text, re-parse, compare; refuse with "layout ..." when the layout cannot be kept) under `_write_lock` with a backup per write (`KEEP_BACKUPS` 30) and `write_atomic`; after a save, `run_import` runs `import_json.gd -- only=<type>/<id>` under the Godot lock or queues an `import` job. The `Hooks` class (3118-3390) is the contract jobs land through: `merge_look` (the sidecar entry merged, `fresh: true`), `merge_top`, `set_recipe`, `merge_recipe`, `set_look_files` (icons via `set_look_icon`: `icon_history` + a backup copy), `redump_merge`, `snapshot_icons`, `look_records`, `content_path`. Look ops (`look_op`): approve, shelve, unshelve, remove (files to `backups/deleted/<id>/<stamp>/`), note, recipe, default.

**Jobs** (`tools/level_editor/jobs.py`, 4,815+ lines; `tools/asset_job.py`): `tools/dl/jobs/queue.json` `{rev, jobs[]}` rewritten whole on every `_save()` (4.0 MB; 467 records, rev 6766: done 429, cancelled 28, failed 8, interrupted 2; kinds icon_cands 225, import 116, look 60, install 32, hero_badge 12, hero_title 11, sim 6, register 4, launch 1; never pruned) plus a folder per job (`job.json`, `log.txt`, `result.json`, `workflows/`). One claimant process (`claim_queue` takes the `jobs` lock with the port in its note; a live second editor is read-only; `recover()` marks running jobs `interrupted`, reclaims dead-pid locks). Four lanes (`comfy`, `godot`, `local`, `sim`), one daemon thread each, FIFO per lane with `front` and `held`. State machine `queued -> running -> done | failed`, `running -> waiting -> pick -> queued` for the human picks, `cancelled`, `interrupted`. `_plan` maps kind+method to an `asset_job.py` subprocess (`ASSET_JOB_SIDECAR=<job>/result.json`), a `steps` list, a launch or a sim. Progress = `parse_line` regexes over the tool's stdout (`render <key> seed N 12.3s ok`, the clip lines, "kept the best", the stop markers) + `_check_caches` every 5 s; **granularity one still or one clip, never a frame or a ComfyUI node**. Landing: `_after_exit` -> `_post` reads `result.json`, merges through the hooks, `_harvest` lists outputs, `_after_done` queues an `import` job. Re-rolls move clip folders to `_old<stamp>` and advance seeds; cancel kills the tree and POSTs `/interrupt` **and `/queue {clear: true}`**.

**Generation** (`tools/gen_art.py`, `gen_ctl.py`, `animate.py`, `artkit.py`, `puppet.py`, `recolour_strip.py`): stills cached `tools/dl/ai_raw_anime/<key>.png + .json` (seed, prompt, refs, the LM Studio `qa()` report, geometry); clips cached `tools/dl/ai_anim/<key>/{out_NN, full_NN, cycle.json}` with per-kind cache-fit rules; frames scaled by a whole-clip statistic (`clip_scale`; gen_ctl: ONE scale for all five views), placed (`place_clip_frames`), colour-corrected, assembled with the procedural sets, packed (`pack_strip`), and the strip + icon **written straight into `game/content/...`** over the previous file; under a job the entry goes to the sidecar, in a hand run the JSON is re-dumped whole (`gen_art.py:1922-1937`). Sizes: 661 clip folders 8.3 GB (666 at 18:40), 3,262 files in `ai_raw_anime` 1.3 GB (each still with its json; 1,633 stills). The only vision QA: `gen_art.qa()` on stills (subjects, background, ground, text, cropped, legs, view, matches) through LM Studio `qwen2.5-vl-7b` and one "faces the viewer?" probe on back/bd pose cycles; never per frame.

**ComfyUI client** (`tools/comfy.py`): `run(graph)` POSTs `/prompt` with a fresh `client_id` then polls `GET /history/<id>` every 1 s; no WebSocket, no node progress; the comfy lock is taken for the whole tool process, no fairness; every graph is saved per job and PUT into the ComfyUI page's user data so a card can open it (`88fits_open`). Graph builders: `klein`, `flux2_dev`, `wan_i2v`, `wan_flf`, `wan_fun_control`, `wan_animate`, the Hunyuan3D graphs, audio, and (in flight) `wan_fun_vace`.

**The installed artifact and the game**: the strip `<id>_sprite[_<x>].png` of square `frame_px` cells, `strip_cols` columns, animations in a fixed order with counts in `anims` (`artkit.ENEMY_ORDER` / `CHAR_ORDER`, `EnemyDef.gd:591-600`, `Player.gd:187`); the look entry `variants[CODE]` = `sprite, icon, anims, strip_cols, fps, head, frame_px (heroes), front_faces/back_faces, note, shelved, fresh, icon_picked, title, recipe`. **No per-frame metadata exists anywhere**; the slot-to-source mapping is recomputed at pack time and never written. The game loads `<id>.tres` at boot (`Registry.gd:67-71`), plays the human-set `variant` / `Save.hero_look` (`Registry.played_look`), one MultiMesh per creature type with `frames/cols/rows` uniforms (`EnemyManager.gd:946-984`).

**Entry points for Claude Code today**: the tool CLIs (each takes its own locks), `POST /api/jobs {kind, target, spec, title}` -> `{job}`, `GET /api/jobs[?since]`, `GET /api/job/<id>` (the record with an 80-line log tail), the `cancel/requeue/pick/install/move/delete/merge/push_workflows` POSTs; `puppet.py stage_looks` is the one script that drives the queue over HTTP. No MCP; no compact result: a job's `outputs[]` are URLs plus a QA problems list per still.

### 1.4 Top five verified blockers to the desired UX

1. **A frame has no identity and no durable home.** Every look run rewrites the strip whole (`gen_art.process` / `gen_ctl.main` `strip.save`), recolour rewrites its destination, and clip frames exist only as cache files that re-rolls move aside (`_move_clips_aside`), that `animate.cache_fits`/`wan_fits` invalidate, that free clips re-cut from `full_NN` (`animate.cycle` 623-635). Map §4.4 shows layer by layer that **no existing layer survives the normal fix paths**; the only safe insertion point is a new per-slot store between the clip cache and the pack, read by an Export that packs with a pinned scale. *In flight*: lane VACE's `frames_store.py` + `frames_export` is exactly that layer; what still overwrites it: hand runs and job landings on pinned slots (Q4), and `gen_art`/`gen_ctl` not registering their frames (AN-10).
2. **State reaches the browser by pull only, at still/clip granularity.** The page polls `rev` every 2 s and gets the whole 3.3 MB list on any change; progress is stdout regexes and cache-file existence; ComfyUI progress is never bridged (the tool polls `/history`; the server never talks to ComfyUI during a render).
3. **The Jobs UI rebuilds DOM on change and keeps interaction state on the DOM** (`sig()`'s time term, `clear(S.groups)`, `c.__picked`, `.jreroll`, the re-pinned log, `assets.js refreshRecord -> redraw` rebuilding the whole editor pane). Structural, not a bug.
4. **Generation, installation and import are one motion with no commit boundary.** The tool writes the PNG into `game/content` as it finishes; `merge_look` sets a page-only `fresh` flag the game ignores; no previous strip is kept (icons are protected, strips are not); a hand run re-dumps the JSON outside the line-preserving writer.
5. **No evaluator looks at frames, and Claude has no compact result.** The only automatic judgments are `qa()` on stills and a few clip heuristics at generation time; a job returns URLs and a log tail, so a session that wants a verdict opens pictures (the spend of 2026-10-20). Related and verified: the comfy lock has no fairness and a hand run can hold it for a whole pass; `_comfy_interrupt` clears ComfyUI's **whole** queue on cancel (an interference bug lane REAL hit the same day).

#### D1 UI (part_UI.md)

**UI-01 (rejected as proposed).** A stream's cadence is bounded by what the server knows: a running record changes when a tool line arrives (`_on_line`), saved at most every 2.0 s (`SAVE_THROTTLE`) or on a cache check (5 s); the unit is a still or a clip. SSE on `BaseHTTPRequestHandler` is feasible (headers without Content-Length, a flush per change, a heartbeat comment every 15 s, one daemon thread per stream, `EventSource` reconnects with `Last-Event-ID` = `rev`), about 150 server lines and 60 client lines, but it adds a thread per tab, a wake-from-sleep failure mode and a file-watch loop for the read-only editor, for ~2 s of latency nobody sees. The dead-simple improvement nobody has made: `parse_line` already recognises `render <key> seed N 12.3s ok`; harvesting outputs on that line instead of on the 5 s workflows-folder check shows a landed still within one poll. The bus is designed so the transport can change underneath it: the page consumes `{rev, changed, removed}` whether it polled or was pushed. Done when a changed poll while one job runs transfers kilobytes, not megabytes.

**UI-02 (accepted).** The architecture already has the right property: the server holds the truth (queue.json, the content JSON, `staged.json`), the page holds a cache plus view state; reconstruction after a reload is a refetch, and "missed events" cannot exist because records are state. Human labels: the lane's `label` = `<CODE>-<n>` is the n-th version **of one slot** (`SP-B-1` = the installed frame, `SP-B-2` the first repair of that slot); it is written into the record and never used as a key (every route takes `version` ids). On its own it is ambiguous (103 slots share "SP-B-1"), so the display label should be `SP-B · run/side · f07 · v2`, with `SP-B-2` only inside the slot's drawer, pending Q1.

### E3. Staging and export: the scenario, concretely

Garry opens an existing Enemy's Look A, replaces run/front frame 7 from Look B's history, regenerates frame 12 with VACE, switches frame 18 to an earlier candidate, keeps browsing, previews, commits once. With the lane's routes:

1. **Open** (`GET /api/frames/enemy/<id>/A`): `look_summary` registers the look if the store has never seen it or the strip changed (written under `tools/dl/frames/...`: cells, twins, group.json; **nothing under `game/`**). The view opens on `run/front`: 12 slots, their versions, flags, driver frames; group tabs with counts; "0 staged".
2. **Frame 7 from Look B** ("From another look" -> `GET .../run/front/others`: B's slots with every version and the warnings; pick B f07 v3 -> `POST .../copy {slot 7, from {...}}`): a new version in A's slot 7 (`source: copied`, `from` = B f07 v3; the raw copied if B had it, sized by A's fit), **staged**. Disk: A's `slot_07/v00N.*`, A's `staged.json`. B untouched. The preview plays the new frame at once; "1 staged".
3. **Frame 12 by VACE** ("Repair" -> `POST .../repair {slots [12], prompt?}`): a `frames_repair` job on the comfy lane (it waits for the lock when a hand run holds it; the demo's runs waited several minutes behind lane REAL's). The slot shows "repairing (job j...)"; Garry keeps editing. Later `vace_repair.py` uploads 25 frames + 25 masks + the reference, runs the graph (140 s on SP-B), keys the taken frame, adds `slot_12/v00N` (`source: vace`), stages it unless pinned (after AN-08's fix: returns it and `_post` stages it), writes the sheet and `result.json`; the card shows before/guide/after and the window; the page learns on the next poll: "2 staged".
4. **Frame 18 to an earlier candidate** ("Versions" drawer -> `POST .../stage {slot 18, version}`): `staged.json` only. "3 staged". `POST .../unstage {slot}` undoes one; without a slot, all.
5. **Browse and preview**: every group's preview composes from effective versions (`effective_cells`); other groups can be staged too; a reload restores everything from the server files.
6. **Commit once** (`POST /api/frames/enemy/<id>/A/export` -> a `frames_export` job on the local lane, 15 s class): `export_look` packs every group's effective cells with `pack_strip`; if the bytes equal the installed strip and nothing is staged it returns `unchanged`; else it copies the old strip to `tools/level_editor/backups/<id>/frames_<stamp>_<sprite>.png`, writes the new PNG via tmp + `os.replace` (**the first write under `game/`**), turns every staged choice into a pinned selection, appends `exports.json`, writes the sidecar entry. Then `_post` -> `merge_look` (the entry's `anims`, `strip_cols`, `head`, `fps`, `sprite`; a JSON backup; `fresh: true` today, to be skipped) -> `on_look_landed` (the store re-reads the strip: hashes match) -> `_after_done` queues `import` (godot lane: `--import`, `lossy_imports`, `--import`, `import_json`). UI: "export A: 3 frames changed", then "import" running, then the look card's `imported` chip; "0 staged".
7. **The game**: the Registry loads `<id>.tres` at the next boot (a running game does not reload); the arena chip or `variant` decides whether A plays. Verification: an arena launch with A.

Failures and reloads: ComfyUI down -> the repair job fails, the slot's badge turns into the card's error, staging untouched. The browser closes -> `staged.json` persists; the repair lands anyway. A crash between the strip write and the commit -> on re-export the same bytes are packed and committed (idempotent; one extra backup). The merge refused for layout -> the job ends `done` with `written.layout: unmerged` (the card offers Merge again / Re-dump); the strip on disk is already new while the entry is old: harmless when `anims`/`strip_cols` did not change, wrong when they did: **that is the rollback gap** (AN-09, engineering). The import fails -> the `.tres` is stale, the page says "not imported", the next import job retries.

The transport can change to SSE under the same consumer when WF-07's rate justifies a thread per tab.

**APIs** (additions only, never renames): `POST /api/requests`, `GET /api/requests[/<rid>]`, `POST /api/requests/<rid>/{cancel,approve,stop}`; `GET /api/job/<id>/summary`; `GET /api/events?since`; `GET /api/ops?days`; `POST .../note` on a frame version; `client_key` and `rev` on the existing POSTs; `/api/frames/...` as built.

**Model boundaries, and where the actors meet**:

```
Claude Code ──art_request.py──▶ POST /api/requests ──▶ requests.py ──▶ jobs.py lanes
      ▲ (text only)                                       │                 │
      └──── GET /api/requests/<rid> (the fold, a sheet path at most)        ▼
                                                                   asset_job.py / vace_repair.py
                                                                   (owns the comfy lock + the
                                                                    ComfyUI session; prints lines)
                                                                                 │

           │
           ▼ flagged items only
   vision_eval.py: LM Studio on the PC (free) ─▶ cheap Claude on contact sheets at decision points (cents, ledger)

```

**Keeping AI commands constrained and non-destructive**: the evaluator produces findings and *named verbs*, never files, shell or ComfyUI calls; `commands.py` refuses unknown keys, out-of-request targets and any verb outside the mode's allow-list (Observe: none; Suggest: `note`; Auto-iterate, if ever enabled: `requeue`, `repair`, `stage`, `ask` on the request's own look within WF-03's budget; never `export`, `default`, `remove`, `delete`, an install over the played icon); every proposal and its outcome is an event and a budget count; the evaluator process has no comfy lock, no ssh key and no `LOCK_HELD_COMFY`; the game's gate (`variant`, `Save.hero_look`) and Export remain human clicks; a strip backup exists on every landing, so nothing automatic is unrecoverable.

### 4.2 Design B (the simpler alternative): no request layer, no events, no commands

Claude queues plain jobs with `art_request.py` and reads `GET /api/job/<id>/summary`; the frames store and Export as built; the deterministic flags and the local VLM as badges; the page fixed in place (UI-04) with the delta poll (UI-02); no `requests.py`, no `events.jsonl`, no `commands.py`, no cheap-Claude tier, no Suggest mode. Cost saved: roughly WF-01 (M) + WF-02 (S) + WF-03 (S) + WF-05 (M) + AI-04's Suggest (S) + AI-07 tier 2 (S). What it loses: Journey 1's single handle over 5-8 jobs (Claude must poll several job ids and fold them itself), the ordered "why did this change" record, any safe way to let an evaluator propose an action, and the ledger that makes a cloud call accountable. **Verdict**: B is a strict subset of A and is exactly Phase 1 below; A's extra layers are added only when their journeys are reached (Phase 3), each behind a gate, so the project never pays for A's generality before it needs it.

### 4.3 How it integrates with the existing code

Nothing is replaced: `asset_job.py`'s argv + sidecar contract, the `Hooks` class, `methods.json`, the cache keys and folders, the Godot and ComfyUI locks, the line-preserving writer, the `since` protocol (`since=0` still returns everything), `puppet.py`'s HTTP client, the arena launch, the look lifecycle (`fresh`/approve/shelve/default), the Drivers viewer's shell and keys, the selftest convention. New behaviour lands as new modules and small insertions in the hot files (`server.py`'s dispatch, `jobs.py`'s `_after_done`/`_post`/`parse_line`, `jobs.js`'s `draw`), each with its own `selftest_<lane>.py` group.

## F6. Critical recommendations

### Top five highest-ROI improvements, ranked

1. **Finish and harden the frame layer lane VACE built (AN-06/08/09/10/14 + WF-04's strip backup).** It is the only insertion point that survives the normal fix paths (blocker 1), it already runs end to end on SP-B, and the hardening is small: one writer of `staged.json`, the shrink guard, the hook after `strip.save`, rollback, retention, a backup on every landing. Without it, every other repair idea is undone by the next re-roll. Journeys 2-5 ride on it.
2. **UI-04, stable cards.** The verified daily annoyance (a running card rebuilt every 2 s, picks and panels lost), fixable in one module with the pattern `looks.js` already follows; it de-risks every later live surface and the Frames view.
3. **AI-05's compact handoff (then WF-01's request fold).** The principal token saver: Claude queues with one command and reads one paragraph plus, at most, one downscaled sheet path; the cost laws measured in part_AI show that the number of pictures in the top model's context, not the model's price, is the lever.
4. **AI-07's tiers with AI-01's ledger, gated by AI-08's blind bench.** Deterministic checks on everything, the free local eye on flagged frames, a pinned cheap Claude model only on contact sheets at decision points under a daily ceiling; the bench stops money being spent on an eye that cannot count (measured: none of the four could).
5. **UI-02's delta protocol and connection line (with WF-06(c)'s cancel fix as its small sibling).** A changed poll goes from 3.3 MB to kilobytes, "offline" becomes a true sentence with a time, a reload returns to the same frame; and a cancel stops clearing a hand run's ComfyUI prompt (a verified interference bug).

### Top five to reject, simplify or defer (defer = sequence, not a fourth status)

1. **UI-03 React/TypeScript/Vite: reject.** A toolchain, a test runner and interop with every imperative component for a rendering-discipline problem a 40-line helper fixes.
2. **UI-01 an event stream now: reject (revisit after WF-07).** The server has nothing sub-second to push; the payload, not the pull, is the cost.
3. **AI-06 `agy`/Antigravity/consumer-OAuth Gemini: reject.** No supported scriptable image route exists; the only honest Gemini route is a paid API key, proven blind first.
4. **WF-02's SQLite and UI-05's separate Art Studio tab: simplify.** An append-only JSONL with a `seq` and an integrated expansion of the look card give the same outcomes without a second truth or a fourth live surface.
5. **Defer**: UI-08's drawn regions until G1 shows a partial mask works; UI-06's substage until WF-07 lands; AI-04's Auto-iterate until G2 shows an eye worth trusting (Auto-select rejected outright); OPS-01's fixtures for streaming/quota/bad-AI-JSON until their features exist; the comfy-lock FIFO ticket unless hand-run contention persists after pass 95.

### What must be preserved to avoid regressions

The `since` contract and its `unchanged` answer (`since=0` returns everything; `puppet.py` and the docs rely on it); the honest `act()` path (busy -> done or refused, no optimistic state); `asset_job.py`'s argv + `ASSET_JOB_SIDECAR` contract and the `Hooks` class; `methods.json` as the catalogue; the cache keys and folders and their fit rules; the line-preserving content writer with its backups; the Godot and ComfyUI locks (one Godot process, one ComfyUI job; `tools/godot.sh`; never break a lock); the look lifecycle (`fresh`/approve/shelve/default) and the arena review of fresh looks; the game's gate (`variant`, `Save.hero_look`); the Drivers viewer's shell and key scheme; the page-free `*_model.js` modules under Node and the no-bundler offline page; the toasts; `staged.json` as the only home of staging; the three dialogs' close -> destroy-players discipline; the small-insertion rule on the hot files while lanes run.

### What to benchmark or prototype before committing

The VACE window (13 vs 25), strength, LoRA vs 20 steps, the pose2 and free2 classes, a partial mask and a cell-space repair (G1); the evaluator models and thresholds on a blind set with Garry as the second rater (G2); the per-record hash cost in `_save` and the delta payload size (UI-02); one devtools session timing `JSON.parse` + `draw()` on today's 3.3 MB answer (UI-04's before number); ComfyUI's WS message shapes on the server (WF-07); a Node DOM stub's adequacy for `draw()` (OPS-01) before any browser harness; the AI Studio key's price and image behaviour, only if Garry buys one (G3).
